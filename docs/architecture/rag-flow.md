# RAG가 작동하는 구간

![RAG 질문 처리 모식도](rag-flow.png)

회색 위쪽은 사전 문서 준비입니다. 공개 PDF를 PyMuPDF로 읽고, 본문을 나눈 뒤 E5로 의미를 숫자로 바꿔 저장합니다. 문서가 바뀌면 준비 과정을 다시 수행하며, 모델을 재학습하는 과정은 아닙니다.

청록색 경계 안은 질문이 들어올 때 작동하는 RAG 흐름입니다.

- **R · Retrieval / 검색:** E5로 질문을 숫자로 바꾸고 NumPy로 저장된 문서 벡터와 비교해 관련 조각 상위 3개를 찾습니다.
- **A · Augmented / 근거 보강:** 원래 질문에 검색한 본문 3개(각 앞 700자)와 조각 ID를 함께 넣어 모델 입력을 구성합니다. 검색 결과가 실제 답변 생성에 전달되는 연결입니다.
- **G · Generation / 생성:** 로컬 Qwen2.5-1.5B-Instruct가 이 입력을 읽고 답변과 인용 ID를 생성합니다. 애플리케이션이 인용 ID를 원문의 쪽 번호·URL로 연결합니다.

질문 → 관련 문서 검색 → 검색 본문을 질문과 함께 모델에 전달 → 근거를 읽고 답변, 이 전체 연결을 RAG로 표시했습니다. R/A/G는 설명을 위한 단계 구분이며 따로 학습한 세 모델을 뜻하지 않습니다. 모식도의 질문과 출력은 관리대장 사례를 이해하기 위한 예시입니다.

구현 근거는 `scripts/ingest.py`, `ragdesk/retrieval.py`, `ragdesk/answering.py`의 `contexts` 구성, `model_server.py`의 입력 메시지 구성입니다. 의미 검색(Dense) 대표 경로이며 BM25·Hybrid 비교는 별도 평가 자료에서 확인할 수 있습니다. 인용 ID 검사만으로 답변 의미의 정확성이 보장되는 것은 아닙니다.

공식 오픈소스 로고를 유지했고, E5는 확인된 공식 심볼이 없어 이름 카드로 표시했습니다. 사용자 요청에 따라 작동 경계와 R/A/G 설명을 모식도 안에 배치했으며, 기능 설명은 흰색 로고 카드 밖에 두었습니다. 공개 문서 기반 개인 PoC입니다.
